# strategies

BookShelf's strategies are the standing approaches for ongoing work: how it is tested, deployed, stored, extended and documented. A strategy says how to work on an area; a [decision record](../decisions/README.md) says why one choice was made. The steps themselves live in the backend and frontend READMEs.

| Strategy | Covers |
|---|---|
| [evals.md](evals.md) | the three kinds of eval, what none of them covers, and where they are headed |
| [deployment.md](deployment.md) | Cloud Run and Firebase: what runs where, the choices behind the deploy, and the security and spend layers |
| [database.md](database.md) | Neon: connection choices, pool sizing, autosuspend and schema changes |
| [nodes.md](nodes.md) | when a new node is the right move, and how to keep the planner's catalog honest |
| [documentation.md](documentation.md) | where each kind of fact lives, and how READMEs, decisions and code comments are written |
